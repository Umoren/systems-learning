
System programming exposes these knowledge:
- what is a process really? 
- What happens when a program reads a file? 
- What does memory ownership mean? 
- How does the operating system schedule work? 
- What sits underneath Node, browsers, databases, containers, and even the AI infrastructure i’ve been working with?
We want to become engineers who can reason further down the stack: from application code into runtimes, processes, memory, operating systems, storage, networks, hardware behaviour, and distributed infrastructure. The career value we get from this comes from that depth. We should eventually be able to look at a slow service, database, runtime, proxy, browser, or distributed system and ask better questions about what the machine is doing underneath the abstraction.
